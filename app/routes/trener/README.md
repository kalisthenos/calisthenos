# app/routes/trener/ — widoki trenera (`/trener/*`)

Trasy panelu trenera (rola `trainer`). Wszystkie pod layoutem `_layout.tsx`,
który wymusza rolę i liczy odznaki nawigacji. Desktop-first. Mapowanie URL w
[`../../routes.ts`](../../routes.ts).

| Plik | URL | Eksporty | Co robi (loader / action) |
|---|---|---|---|
| `_layout.tsx` | `/trener` (layout) | loader, default | Wymaga roli trenera; **wszystkie** liczniki nawigacji jednym wywołaniem `loadTrainerNavigation` (`lib/views`) — trasa nie dotyka bazy. `nav.trainees` liczy podopiecznych z AKTYWNĄ relacją prowadzenia (do integracji licznik celowo obejmował też zarchiwizowanych — odwróciła to decyzja D3 specu); odznaka „Pomysły" = `nav.newFeatureRequests` — wyłącznie zgłoszenia w statusie `new` (tak liczy BE): sygnał „przyszło coś nowego", dlatego NIE liczy wszystkich. Topbar + sidenav + `<Outlet/>`. |

| `biblioteka.nowe.tsx` | `/trener/biblioteka/nowe` | loader, action, default | Formularz nowego ćwiczenia (nazwa, jednostka REPS/SEC, opis, checkbox „Zbieraj RPE", tagi, demo wideo). Zapis (gałąź domyślna akcji): `updateExercise(api, input)`, bez pre-odczytu — własność i sprzątanie starego demo egzekwuje `PATCH` po stronie BE; `UploadError` mapowany na komunikat w formularzu jak w `biblioteka.nowe.tsx`. Trasa nie dotyka bazy. Kliencki limit demo z loadera; przycisk „Zapisz zmiany" blokowany na czas wysyłki. |

Karta wyniku zaznacza, gdy zaproszenie niesie formularz. |

Trasa nie trzyma `db` — ostatni powód, dla którego go trzymała, zniknął razem z płatnościami (ADR-0037). Nazwa i `404` dla cudzego: `findTraineeRef` (luka L S5-2); data dołączenia zniknęła z podtytułu — kontrakt jej nie niesie.
